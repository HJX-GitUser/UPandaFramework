## 0.5 先弄清三个基本概念

- **比较排序 vs 非比较排序**：前 7 种只通过"两两比较大小"排序，最坏下界是 $\Omega(n\log n)$；计数/基数排序**不做比较**，靠统计/按位分配，所以能突破 $n\log n$ 的下界，但要求元素是**整数且范围有限**。
- **原地排序（in-place）**：只使用 $O(1)$ 额外空间（递归栈除外）。
- **稳定性**：例如按"分数"排序后，"同分的人"顺序不应被打乱——排序对象若带有其它字段，稳定排序才有意义。

**调用方式**（本文件均为静态嵌套类，直接调用即可）：

```csharp
int[] a = { 3, 1, 4, 1, 5, 9, 2, 6 };

SortStu.BubbleSort.Sort(a);      // 原地修改 a
SortStu.MergeSort.Sort(a);

int[] b = SortStu.CountingSort.Sort(a);         // 计数排序：自动探测范围，返回新数组
int[] c = SortStu.CountingSort.Sort(a, 0, 9);   // 也可手动指定范围
```

## 1. 冒泡排序（BubbleSort）——"相邻交换，大的上浮"

**思想**：重复扫描数组，比较相邻两数，**逆序就交换**，每轮把当前范围内最大的数"冒泡"到末尾。第 $i$ 轮后，最后 $i$ 个元素已就位，因此内层只需比较到 `n - i - 1`。

**代码要点**：

```csharp
for (int j = 0; j < n - i - 1; j++)
    if (arr[j] > arr[j + 1]) { Swap(arr, j, j + 1); swapped = true; }
if (!swapped) break;   // ★ 优化：本轮无交换 → 已经有序，提前终止
```

- **稳定性** ✅：只有 `>` 才交换，相等元素不会互换位置。
- **优化亮点**：`swapped` 标志让**已有序**数组只需一趟（最好 $O(n)$）。
- **适用**：几乎不用在工程里（太慢），仅适合教学与"近乎有序 + 数据量极小"的场合。

---

## 2. 选择排序（SelectionSort）——"每轮挑最小的放前面"

**思想**：第 $i$ 轮在未排序区 `[i, n-1]` 里找最小值的下标 `minIdx`，与 `arr[i]` 交换。

**代码要点**：

```csharp
int minIdx = i;
for (int j = i + 1; j < n; j++)
    if (arr[j] < arr[minIdx]) minIdx = j;
if (minIdx != i) Swap(arr, i, minIdx);
```

- **不稳定** ❌：交换可能跨越多个相等的元素。例如 `[5a, 5b, 3]`，第一轮把 3 换到最前时，`5a` 被换到了 3 的位置，导致 `5a` 跑到 `5b` 之后。
- **特点**：**交换次数最少**（至多 $n-1$ 次），适合"写操作代价极高"（如闪存）的场景；但比较次数固定为 $O(n^2)$，与数据是否有序无关。
- 与冒泡对比：冒泡交换多、可提前终止；选择交换少、但**无法提前终止**。

## 3. 插入排序（InsertionSort）——"像抓扑克牌一样插入"

**思想**：把数组看成「已排序前缀 + 一个待插入元素」。每轮把 `arr[i]` 记为 `key`，在已排序前缀里**从右往左**找位置，边找边把比 `key` 大的元素往后挪，最后把 `key` 放进空位。

**代码要点**：

```csharp
int key = arr[i];  int j = i - 1;
while (j >= 0 && arr[j] > key) { arr[j + 1] = arr[j]; j--; }
arr[j + 1] = key;
```

- **稳定性** ✅：用的是 `arr[j] > key`（严格大于才移动），相等元素不移动。
- **最擅长的场景**：**数据基本有序**时，内层循环几乎不执行，最好 $O(n)$；因此常作为快排/归并在小数组时的收尾。
- **进阶变体 `SortWithBinarySearch`**：用二分查找定位插入点，把**比较**从 $O(n)$ 降到 $O(\log n)$；但**移动元素仍是 $O(n)$**，所以总复杂度不变，只是减少了比较次数。
  - ✅ 稳定性处理：二分查找返回"**第一个大于 key 的位置**"（越过所有相等元素），因此二分变体同样保持稳定。

## 4. 希尔排序（ShellSort）——"插入排序 + 大步长预排序"

**思想**：插入排序对"接近有序"的数据很快。希尔排序先用**较大的间隔 gap** 做分组插入排序，让数据"大致有序"，再不断缩小 gap，最后一次 `gap = 1` 就是普通插入排序——此时数据已基本有序，代价很低。

**代码要点**（Knuth 增量序列 $1,4,13,40,\dots$）：

```csharp
int gap = 1;
while (gap < n / 3) gap = gap * 3 + 1;   // 生成初始最大间隔
while (gap > 0) {
    for (int i = gap; i < n; i++) {      // 对间隔 gap 的子序列做插入排序
        int temp = arr[i]; int j = i;
        while (j >= gap && arr[j - gap] > temp) { arr[j] = arr[j - gap]; j -= gap; }
        arr[j] = temp;
    }
    gap /= 3;                            // 缩小间隔
}
```

- **稳定性** ❌：不同 gap 的子序列交换会让相等元素的相对顺序漂移。
- **复杂度依赖增量序列**：Knuth 序列平均约 $O(n^{1.3})$ 左右，最坏 $O(n^2)$。
- **适用**：中等规模、对内存敏感且不要求稳定的场景；代码简单，是 $O(n^2)\to O(n\log n)$ 之间的折中。

## 5. 归并排序（MergeSort）——"分治 + 合并两个有序数组"

**思想**：递归地把数组**对半切**，直到只剩一个元素（天然有序），再逐层**合并**两个有序段。合并时开一个临时数组，双指针比较左右两段，把较小者依次放入。

**代码要点**：

```csharp
// 入口一次性分配 temp，避免每层递归重复 new —— 工程级优化
int[] temp = new int[arr.Length];
Sort(arr, 0, arr.Length - 1, temp);

// 合并时用 <= 保证稳定
if (arr[i] <= arr[j]) temp[k++] = arr[i++];
else                  temp[k++] = arr[j++];
```

- **复杂度恒定**：无论数据如何都是 $O(n\log n)$，最坏也不退化——这是它比快排稳的地方。
- **稳定性** ✅：合并时取左边（`<=`）优先。
- **代价**：需要 $O(n)$ 额外空间（本实现把 `temp` 提到入口分配，避免递归中反复 GC，值得学习）。
- **适用**：对稳定性有硬要求、数据量大且不在乎额外空间；常用于外部排序（磁盘归并）。

## 6. 快速排序（QuickSort）——"选基准，把小的放左边、大的放右边"

**思想**：每轮选一个**基准 pivot**，通过**分区（Partition）**把数组整理成「左 < pivot < 右」，pivot 落位后，再对左右两侧递归排序。

**代码要点**（Lomuto 分区，取最后一个元素为 pivot）：

```csharp
int pivot = arr[right];
int i = left - 1;                       // i 指向"小于 pivot 区"的末尾
for (int j = left; j < right; j++)
    if (arr[j] <= pivot) { i++; Swap(arr, i, j); }
Swap(arr, i + 1, right);                // pivot 归位
return i + 1;
```

- **不稳定** ❌（尽管用了 `<=`，交换仍会打乱相等元素相对顺序）。
- **平均 $O(n\log n)$，最坏 $O(n^2)$**：若数据**已经有序**且固定取末尾作 pivot，分区会严重失衡。因此排序入口**默认调用 `PartitionMedianOfThree`（三数取中）**：取 `left/mid/right` 的中位数为基准，可有效避免已有序数组退化为 $O(n^2)$。
- **适用**：通用排序首选（.NET/C++ 标准库都基于它），缓存友好、常数小；对"已有序/大量重复"数据要配合随机化或三数取中。

## 7. 堆排序（HeapSort）——"用完全二叉树选出最大"

**思想**：把数组看成一棵**完全二叉树**（下标 $i$ 的左子 $2i+1$、右子 $2i+2$）。先自底向上**建最大堆**（堆顶是最大值），然后反复把堆顶与末尾交换、缩小堆并**下沉调整**。

**代码要点**：

```csharp
for (int i = n / 2 - 1; i >= 0; i--) Heapify(arr, n, i); // 1. 建堆（从最后一个非叶节点开始）
for (int i = n - 1; i > 0; i--) {
    Swap(arr, 0, i);       // 2. 把最大值放到末尾
    Heapify(arr, i, 0);    // 3. 对缩小的堆重新堆化
}
```

- **所有情况都是 $O(n\log n)$**、**原地 $O(1)$ 空间**——这是它相对快排/归并的独特优势。
- **不稳定** ❌：堆顶与末尾的长距离交换极易破坏相等元素顺序。
- **缺点**：常数较大，且对**缓存不友好**（跳着访问下标），实践中通常不如快排快。
- **适用**：需要严格 $O(1)$ 额外空间 + 稳定 $O(n\log n)$ 最坏时间，或在"每次取最大/最小"的**优先队列/TopK** 场景。

## 8. 计数排序（CountingSort）——"用下标统计出现次数"

**思想**：不比较，直接开一个长度为**数值范围**的计数数组，统计每个值出现次数，再根据累积次数把元素放回正确位置。

**代码要点**：

```csharp
int range = maxValue - minValue + 1;      // 必须事先知道 min/max
int[] count = new int[range];
// ① 统计频次
foreach (int num in arr) count[num - minValue]++;
// ② 前缀和 → 每个值"最后应出现的位置"
for (int i = 1; i < range; i++) count[i] += count[i - 1];
// ③ 从后向前填 output → 保证稳定
for (int i = arr.Length - 1; i >= 0; i--) {
    output[count[arr[i] - minValue] - 1] = arr[i];
    count[arr[i] - minValue]--;
}
return output;                            // 返回新数组，非原地
```

- **复杂度 $O(n+k)$**，其中 $k=$ 范围。当 $k$ 远小于 $n\log n$ 时非常快。
- **稳定性** ✅：关键在**第 ③ 步从后往前填**——相同值中靠后的元素先被放到更靠后的空位。
- **限制**：只能排整数，且**范围不能太大**（否则 $k$ 巨大浪费内存）。
- 提供两种入口：`Sort(arr)` 会**自动探测 min/max**；`Sort(arr, minValue, maxValue)` 可手动指定（范围已知时可少一次遍历）。对 null / 空数组 / 非法范围均做了安全处理。
- **适用**：年龄、成绩、0~N 编号等范围集中的整数。

## 9. 基数排序（RadixSort）——"按位多次计数排序"

**思想**：整数拆成个、十、百……每一位，**从低位到高位（LSD）**依次做一次稳定排序。因为每轮稳定，高位轮次不会破坏低位的相对顺序。

**代码要点**：

```csharp
int max = GetMax(arr);                    // 决定最大位数
for (int exp = 1; max / exp > 0; exp *= 10)
    CountingSortByDigit(arr, exp);        // 对当前位做一次"基数10"的计数排序
// 每一位：digit = (arr[i] / exp) % 10
```

- **复杂度 $O(d(n+k))$**：$d$ 为位数，$k=10$（十进制）。位数通常很小，因此实际近似 $O(n)$。
- **稳定性** ✅：底层是稳定计数排序，从低位到高位累积保持全局有序。
- **支持负数**：实现先对全数组做**整体平移**（减去最小值，用 `long` 防止 `int.MinValue` 溢出），使所有数非负后再按位稳定排序，因此正负整数都可正确排序。
- **适用**：大量、等长/范围可数字化元素的排序（电话号码、学号、多关键字）。

## 附：怎么选排序算法？

```mermaid
flowchart TD
    A{元素是整数且范围小?} -->|是| B[计数/基数排序]
    A -->|否| C{对稳定性有要求?}
    C -->|是| D{允许 O(n) 额外空间?}
    C -->|否| E{最坏时间不能退化到 O(n²)?}
    D -->|是| F[归并排序]
    D -->|否| G[插入排序 或 冒泡<br/>（数据量小/近有序时）]
    E -->|是| H[堆排序 O(1) 空间]
    E -->|否| I[快速排序<br/>最好配三数取中/随机基准]
```

**实践建议（面试 & 工程）**：
1. **数据量小（< 50）或近乎有序** → 插入排序（常数小、实现简单）。
2. **通用大数组** → 快速排序（配随机化/三数取中），C# 可直用 `Array.Sort`。
3. **要求稳定且不在乎空间** → 归并排序。
4. **要求 O(1) 空间且最坏稳定 O(n log n)** → 堆排序。
5. **整数且范围集中** → 计数排序；**范围分散但位数少** → 基数排序。
