# 热更耗时与磁盘管理

日期：2026-11-06。基线：`5b9fe9e`。本轮完成启动热更的文件阶段优化与磁盘生命周期管理，未修改业务场景、预制体、已有远端清单或用户缓存。

## 问题与修复

| 原行为 / 复现 | 修复后行为 | 验证 |
|---|---|---|
| UPGameRoot 在 Unity 续体中同步 MD5、备份、复制及恢复；大文件阻塞帧循环 | HotUpdateStorage 把文件校验、规划、恢复、提交和回收放到工作线程；Unity API 只在主线程调用 | 16 MiB PlayMode 校验允许主循环推进；32 MiB Player 对照原同步 MD5 路径 |
| 暂存、备份及目标增长没有联合预算 | 清单下载前检查其上限；包下载前检查暂存、登记缓存、实际可用空间；提交前复查空间 | 暂存/缓存超限、设备空间不足、查询失败和下载后空间减少 |
| 下载写入没有字节上限，未知 Content-Length 可继续占盘 | DownloadItem.maximumBytes / 文件句柄在写入前检查总长度，包含续传起点；热更包上限等于清单声明大小 | 原生 HTTP 超限失败、直接数据块越界、续传上限 |
| 原生请求仍可报告 Success，脚本句柄已拒写却被判成功 | Downloader 独立检查 WriteFailed；Content-Length 真正到达才停止读取响应头 | 原生 HTTP 测试曾复现 Completed，修复后为 Failed，文件不超限 |
| 所有旧 stage 被删除，退出后写入句柄可能未释放 | 每次 stage 有格式化归属标记和独占租约；仅清理合法且可独占的本目录；取消先关闭写入再 Abort | 未登记目录、旧版目录保留；Root 销毁后部分下载暂存被清理 |
| 旧包持续累积，缺少回收边界 | 增加按资源根目录隔离的缓存登记，保护当前、随包和保留历史清单引用，仅回收本更新器写入且内容未变的文件 | 历史保留/过期、随包引用、未知文件、外部修改、损坏登记、缺少随包清单 |
| 销毁后的提交续体不能可靠收尾 | 生命周期取消令牌；文件复制分块检查取消；日志建立后取消会在后台恢复旧文件，失败保留恢复日志 | 提交途中取消还原全部旧文件；恢复日志先完整验证目标，再执行恢复 |
| 已加载或正在加载的 AB 可能与文件维护重叠 | 启动维护与框架 AB 加载互斥；已有原生 AB 时拒绝更新，等待不阻塞主线程 | 互斥门等待用例、真实 Player 已加载 AB 拒绝维护 |

下载器额外修正：禁用/销毁时结束等待并释放请求；重试使用真实时间，暂停游戏时仍能取消；开始/进度回调禁用组件后不访问已释放的原生请求。旧三参数 DownloadHandlerFile 构造和 DownloadAsync 保持可用，一般下载默认不限字节。

## 文件与数据流程

1. 捕获 Unity 路径及配置，在主线程取得文件维护租约。关闭热更时只检查是否需要恢复；无需恢复时保持原有随包启动流程。
2. 工作线程取得 `AssetBundles/.update.lock` 的独占句柄；先恢复 `.update-recovery/journal`。恢复失败停止启动，避免使用混合版本。
3. 在 `.update-stage/<资源根摘要>/<随机会话>/` 创建独占 `.owner`。128 位目录摘要缩短 Windows 路径，登记内仍校验完整资源根；较长缓存根路径已加入回归。
4. 下载并解码清单，校验现有 Persistent 包的大小与 MD5，只下载缺失/损坏/变更的包。Persistent 包必须提供正数大小及合法 MD5。
5. 回收不影响当前本地版本的可回收文件，再检查预算。下载后重新核验文件和清单；包、登记、清单加入同一个可恢复事务，清单最后提交。
6. 提交后回收已过保留期的文件，登记维护仍使用受验证事务。无法完成恢复时不初始化资源系统。回收失败保留文件并记录警告。
7. 关闭写入、释放 stage 及维护租约。Root 销毁触发后台收尾，不依赖已销毁对象的 Unity 续体；有遗留恢复日志时下一次启动继续恢复。

控制区和设备保留文件名不能用作包目标；拒绝路径越界、重复/文件目录冲突，以及路径中的重解析点。恢复日志校验所有目标后才开始复制。相对路径属于框架数据上下文，不能通过恢复日志写到外部目录。

登记位于 `.update-state/<资源根摘要>/ledger.data`，采用前轮版本化字段图并校验完整性。登记损坏或随包清单不可用时，本轮跳过旧包回收；不会据此扫描删除未知文件。切换 LoadAssetPath 后不同根目录的登记保持隔离。

## 配置及默认值

新增 `UPGameRoot.Config.hotUpdate`，Inspector 的“热更磁盘管理”可编辑。旧 Json 通过预置默认对象 + FromJsonOverwrite 读取；缺少整个配置或其中个别字段时保持默认值。

| 字段 | 默认 | 语义 |
|---|---:|---|
| minimumFreeSpaceMB | 64 | 设备至少保留 64 MiB 可用空间；查询失败拒绝本轮下载。0 关闭设备空间探测 |
| maximumStagingMB | 0 | 本批次清单、下载包、登记的逻辑字节上限；0 不额外限制，清单仍有 64 MiB 格式上限 |
| maximumManagedCacheMB | 0 | 当前资源根的登记缓存预算；0 不额外限制，不包含未登记用户文件、其他根目录或完整 persistentDataPath |
| retainedManifestCount | 2 | 保护最近 2 份已提交清单的引用，包含当前；限制在 1–10 |
| collectUnusedBundles | true | 启用有归属和摘要校验的旧包回收 |

空间估计包括尚待下载的包、登记暂存、旧目标备份、各目标正增长，以及 1 MiB + 每文件 8 KiB 的元数据余量。已有清单暂存已反映在可用空间中。预算保守计算，当前版本或保留引用不会为满足限额被强制删除；空间不足走验证后的本地清单/随包降级。

旧版未登记 AB、未带有效归属标记的 stage、用户文件和 `.legacy.bak` 不会自动删除。若要回收历史遗留文件，需另做离线归属清点；本轮不会盲目接管。保留历史清单引用不等于保留被同名覆盖的旧包字节，不提供整版本回滚能力。

## 边界

- 本轮验证平台为 Windows/Mono；未验证移动设备、IL2CPP、WebGL 或断电后的文件系统耐久性。
- WebGL 使用保留兼容的单线程文件阶段，不能据此宣称后台性能提升；设备可用空间查询不可用时需按平台配置 minimumFreeSpaceMB，仍可保留逻辑预算。
- 下载沿用 Unity DownloadHandlerScript 写盘；大文件 MD5、备份、提交与回收已移出主线程，未新增独立下载写入队列。
- 原生 AB 状态检查和框架加载门用于启动更新；业务若直接绕过框架调用 Unity AssetBundle API，仍需自行协调维护时机。HotUpdateStorage 是纯文件服务，单独使用时由调用方保证目标目录没有活动资源读取。
- 同一 persistent 根并发维护会被拒绝；恢复日志属于创建它时的资源根上下文。恢复未完成前不要更换 LoadAssetPath。
